Vas a construir "OidcMock": un servidor OpenID Connect falso, para desarrollo local y offline, en .NET 10 (C# 14).

OBJETIVO
Imitar el comportamiento observable del servidor https://oauth2.example.com/personafisica/ según su openid-configuration (pegado al final de este prompt), para que mis aplicaciones puedan apuntar al mock sin cambios de código.

REGLAS INNEGOCIABLES
1. TDD estricto: por cada comportamiento, primero escribes un test que falla (Red), muestras que falla, implementas lo mínimo (Green), y luego refactorizas. Un commit por ciclo con mensaje convencional (test:/feat:/refactor:).
2. Dependencias mínimas. Producción: solo el framework + Microsoft.IdentityModel.JsonWebTokens. Tests: xunit.v3 + Microsoft.AspNetCore.Mvc.Testing. Cualquier otro paquete requiere que me lo propongas y justifiques antes.
3. Sin base de datos. Configuración y datos en archivos JSON (clients, users, scopes, signing key). Tokens, códigos y refresh tokens viven en memoria.
4. Estructura: src/OidcMock.Core (dominio + casos de uso, SIN referencia a ASP.NET), src/OidcMock.Host (Minimal APIs, stores JSON, crypto), tests/OidcMock.UnitTests, tests/OidcMock.IntegrationTests. Usa solución .slnx.
5. Clean Code: nombres que revelan intención, funciones cortas, una responsabilidad por clase, sin comentarios que expliquen lo obvio, sin números/strings mágicos (constantes o enums), nullable habilitado, warnings como errores.
6. Patrones: Strategy para grant types, Repository de solo lectura para stores, Options pattern para configuración, Result<T> para errores de negocio, TimeProvider para el reloj, inyección de dependencias por constructor.
7. Errores de protocolo según RFC 6749/6750/7009/7662 (invalid_request, invalid_client, invalid_grant, unsupported_grant_type, invalid_scope, etc.) con los códigos HTTP correctos.
8. Al terminar cada prompt: dotnet build y dotnet test en verde, y un resumen de 5 líneas máximo de lo hecho y de las decisiones que tomaste.

Si algo es ambiguo, haz la suposición más simple, anótala en docs/decisions.md y continúa; no me hagas preguntas salvo que bloquee.

MEMORY BANK
El directorio `memory-bank/` es un Memory Bank según las buenas prácticas de Cline
(https://docs.cline.bot/best-practices/memory-bank) y es la única fuente de verdad entre sesiones.
Mantén sus archivos en español y actualiza `active-context.md` y `progress.md` al empezar y al
terminar cada tarea, además de `file-index.md` al agregar o eliminar archivos y `tech-decisions.md`
al tomar una decisión. Está en `.gitignore` a propósito: es contexto local de trabajo, no se versiona.
El histórico de decisiones con su porqué vive commiteado en `docs/decisions.md`.
